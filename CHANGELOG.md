## 0.3.0 — по итогам аудита (12.10.2026)

Плагин переехал из каталога файлов Пульса в репозиторий pulse-assist/pulse-browser и в публичный каталог плагинов.

**Безопасность**
- Оплату и оформление заказа подтверждает только владелец — кнопкой на странице плагина. Раньше агент мог сам
  вызвать `pulse browser confirm`. Пульс сообщает, кто зовёт (`X-Pulse-Caller`, контракт 1.7).
- Подтверждение одноразовое и на одно действие (тот же элемент на той же странице). Раньше одобренный id действовал
  на любое число действий до перезапуска.
- Режим `write` включает только владелец (агент мог сам переключить сессию).
- Ввод в живом просмотре — только владелец.

**Агенту работать с реальными сайтами**
- `snapshot` по умолчанию — элементы со ссылками `e1, e2…` (метка `data-pulse-ref`) и текст страницы. Раньше ссылки
  `ax:N` нельзя было передать в `click`: агенту оставалось угадывать CSS-селекторы.
- Клик — настоящими событиями мыши в центр элемента (перекрытый — через DOM), ввод — `Input.insertText` с запасным
  путём через «родной» setter: React-поля раньше не видели ввода.
- `download` — файл по ссылке с куками и прокси сессии.
- «Сайт не открылся: net::ERR_…» вместо «успеха» на странице ошибки Chrome; подсказка про прокси.
- Распознавание проверок «вы не робот» (`blocked` и подсказка).
- Повисший после ошибки сайта Chrome перезапускается сам (раньше каждая команда падала по таймауту CDP).
- Без «HeadlessChrome» в User-Agent, без флага автоматизации, русский язык, часовой пояс из настроек.

**Ресурсы и интерфейс**
- Chrome закрывается после `idle_minutes` без дела; открыть страницу плагина больше не значит запустить Chrome.
- Скриншоты — только шаги агента, последние `keep_screenshots` на сессию (за сутки 0.2 накопила 266).
- `check` не создаёт служебную сессию `healthcheck`; проверяет прокси сессий.
- Подписи по-русски; запрос подтверждения — что именно и где, скриншот, «Разрешить один раз» / «Отклонить».
