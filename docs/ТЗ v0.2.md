# ТЗ v0.2 — плагин «Браузер»

Версия плагина: 0.2.0. Контракт v0.1 сохранён: raw CDP, Docker, персистентные профили, proxy на сессию,
один writer, секреты не в чате, артефакты в `@browser/<session>/`.

## Состав

1. **Live view.** Page.startScreencast (JPEG q60, до 1280×800). Сервер хранит последний кадр; страница
   плагина long-poll'ит `GET /sessions/<имя>/frame?since=<seq>&wait=2` (≤10 с). Ввод владельца —
   `POST /sessions/<имя>/input` {kind: click|mousedown|mouseup|move|wheel|press|type}; type = Input.insertText
   (кириллица, вставка). Screencast останавливается сам через ~20 с без запросов. noVNC не понадобился.
2. **Вкладки.** Один CDP-клиент на активную вкладку; переключение = переподключение к target. Номера
   стабильны (порядок первого появления, а не порядок /json/list). Команды: `tabs`, `tab new|select|close`,
   `--tab` у остальных; `open --new_tab`. Закрытая страницей вкладка → автоперепривязка к первой живой.
3. **Ожидания.** `wait` (selector видимый | url подстрока/`re:` | text | networkidle | ms | timeout) и
   `--wait_*` внутри open/click/type/press/select/tab new. Таймаут не бросает ошибку: `ok:false`.
   networkidle — нет запросов в полёте 500 мс (по Network.* событиям; вечные SSE/WebSocket-запросы дадут таймаут).
4. Клавиши агента: `press` теперь шлёт windowsVirtualKeyCode (Enter, Tab, Backspace, стрелки…).

## Проверено (smoke 12.10.2026)

check → session → open (+wait) → tab new/select/close → wait ok/timeout → click в нужной вкладке → snapshot →
frame/input на data:-странице: клик по координатам, русский текст, Enter, колесо дошли до страницы.
Страница плагина в реальном браузере владельца не открывалась (нужен пароль владельца): UI проверен `node --check`.
